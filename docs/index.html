setthemacup

A fresh Mac, set up in one command.

My whole dev environment: tools, apps, dotfiles, keys and 106 macOS settings. You pick what runs from a checklist, and every change it makes is listed below.

curl -fsSL https://raw.githubusercontent.com/mahi160/setthemacup/main/bootstrap.sh | bash

The run

Eleven steps, in this order

You answer everything in the first few minutes: your Mac password, the checklist, a GitHub login in Brave and SSH passphrases. Then it runs on its own. Homebrew always runs; everything else is a checkbox, all on by default. Each step checks what's already done, so running it again only fills the gaps.

  1. 01

    Homebrew --only homebrew always runs

    Package manager everything else installs with

    • Installs Homebrew to /opt/homebrew (non-interactive, uses the sudo session)
    • Adds brew shellenv to ~/.zprofile
    • Removes group write on /opt/homebrew/share so oh-my-zsh's compaudit stays quiet
  2. 02

    CLI tools --only cli

    git, neovim, tmux, fzf, lazygit, gh, … (Homebrew formulae) + pnpm globals (pi)

    • Installs 19 formulae from installer/src/data/apps.json in one batched brew install
    • Taps third-party taps first; retries one by one if the batch fails
    • Git: git, gh, git-delta, lazygit
    • Editor: neovim, tree-sitter-cli, ripgrep, fd
    • Terminal: tmux, fzf, stow, fastfetch, onefetch, nowplaying-cli
    • Dev: lazydocker, lazysql
    • System: terminal-notifier, mole, openfortivpn
    • pnpm globals (latest, pnpm add -g): @earendil-works/pi-coding-agent
  3. 03

    Private settings --only private

    Restore private.env, VPN gateways and local aliases from your private GitHub repo

    • Logs in with gh, then clones <you>/setthemacup-private (private) to ~/.config/setthemacup over HTTPS
    • No such repo yet: asks for each value once, then creates the private repo from your answers
    • Already cloned: pulls the latest
    • Links local.zsh into ~/.config/zsh; the daily sync commits and pushes any changes

    Pulls in gh git

  4. 04

    Dotfiles + theme --only dotfiles

    oh-my-zsh, then link zsh, git, ghostty, tmux, nvim, lazygit, fastfetch, pi configs

    • Clones oh-my-zsh to ~/.oh-my-zsh and zsh-autosuggestions, zsh-syntax-highlighting, zsh-completions into ~/.config/zsh/plugins
    • Links dotfiles/{zsh,git,ghostty,tmux,nvim,lazygit,fastfetch,pi,stow} into $HOME with GNU stow
    • Real files in the way are moved to ~/.setup-backup/<date>/ (paths kept), never overwritten
    • Creates the theme links (theme state in ~/.config/theme, default kanagawa-wave)

    Pulls in stow git

  5. 05

    Git + SSH --only git

    Git identity (personal + work via includeIf), SSH keys, optional upload to GitHub

    • ~/.gitconfig is stowed from dotfiles/git (delta pager, sane defaults, no identity)
    • ~/.gitconfig.local gets [user] from private.env plus an includeIf that switches to the work identity under $WORK_DIR
    • ~/.ssh/config is stowed; work host alias goes in ~/.ssh/config.local
    • Up front: asks a passphrase for each new ed25519 key (stored in the macOS Keychain), then logs in with gh and uploads each key to its GitHub account

    Pulls in gh stow

  6. 06

    Neovim --only nvim

    LazyVim plugins synced headlessly

    • Runs nvim --headless "+Lazy! sync" then "+Lazy! clean" against the stowed LazyVim config
    • Mason installs language servers on first interactive start

    Pulls in neovim git ripgrep fd tree-sitter-cli

  7. 07

    AI skills --only ai

    Agent skills for pi (pi itself is a pnpm global under CLI tools)

    • Skills via npx skills@1.7.4 add <repo> --skill … -g --agent pi into ~/.agents/skills:
    • vercel-labs/skills: find-skills
    • Leonxlnx/taste-skill: design-taste-frontend
    • GoogleChrome/modern-web-guidance: modern-web-guidance
    • mattpocock/skills: grill-me, to-spec, to-tickets, tdd, diagnosing-bugs, triage, implement, code-review, improve-codebase-architecture, setup-matt-pocock-skills
  8. 08

    Extras --only extras

    Helper commands, Swift tools, Pokemon background, SMB auto-mount, weekly cleanup jobs

    • Links every file in bin/ into ~/.local/bin (dev, note, vpn, theme, pokemon-bg, setup, tmux widgets, …)
    • Compiles installer/swift/*.swift into ~/.local/bin when the source changed
    • Downloads a starter Pokemon for the Ghostty background and builds the pi notification icon
    • One LaunchAgent per SMB share in private.env (mounts on login via Finder + Keychain)
    • Weekly LaunchAgents: pi-prune, fnm multishell cleanup, brew/pnpm cache cleanup (replaces crontab)
    • Daily setup --sync: anything you brew install, pnpm add -g or skills add by hand lands in the manifest (category Inbox); removals drop out; you get a notification and commit when ready
  9. 09

    flowd --only flowd

    Coding-time tracker: install fw, restore the journal, AI summaries with Haiku

    • Installs fw from github.com/mahi160/flowd releases into ~/.local/bin (no sudo)
    • Clones the journal repo (FLOWD_JOURNAL_REMOTE in private.env) to ~/.local/share/flowd/journal
    • Restores flowd.db from the journal repo's private db-backup release (fallback: ~/flowd-backup.zip); never overwrites
    • Backs the database up daily (flowd-backup: sqlite snapshot, gzip, replaces the release asset — no git history growth)
    • Writes ~/.config/flowd/config.yaml with ai_command: pi -p --model anthropic/claude-haiku-5-5:low
    • tmux.conf starts the daemon (fw start) whenever tmux starts

    Pulls in tmux git

  10. 10

    GUI apps --only apps

    Ghostty, Brave, Tinycast, Slack, OrbStack, fonts, … (Homebrew casks)

    • Installs 20 casks from installer/src/data/apps.json in one batched brew install
    • Taps third-party taps first; retries one by one if the batch fails
    • Terminal: ghostty
    • Browser: brave-browser
    • Productivity: tinycast, obsidian, alt-tab, shottr
    • Chat: slack, whatsapp, telegram
    • Utilities: localsend, mos, doll, stats
    • Network: tailscale-app
    • Dev: orbstack
    • Media: iina, transmission, tbis
    • Fonts: font-cascadia-code-nf, font-jetbrains-mono-nerd-font
  11. 11

    macOS settings --only macos

    106 system defaults (Dock, Finder, keyboard, trackpad, …), Caps Lock → Control, display scaling

    • Applies the defaults table in installer/src/data/defaults.ts (Dock, Hot corners, Spaces & windows, Finder, Dialogs, Keyboard, Trackpad, Screenshots, Menu bar, Speed & appearance, Privacy & noise); only drifted values are written
    • Restarts only the affected apps (Dock, Finder, SystemUIServer)
    • Frees ⌘Space from Spotlight for Tinycast
    • Caps Lock → Control via a hidutil LaunchAgent (no Karabiner)
    • No startup chime (nvram, needs sudo)
    • Display scaling "More Space": the largest HiDPI mode of the built-in display

The lists keep themselves current

Every day at noon, setup --sync compares what's installed with the day before. Something you brew install, pnpm add -g or npx skills add by hand is appended under Inbox with its description. Something you uninstall drops out. A notification tells you what changed, and you commit when you're ready.

Kept out of the repo

Private values

This repo is public. Git identity, work folder, notes vaults, SMB shares, VPN gateways and machine-only aliases live in a separate private GitHub repo, <you>/setthemacup-private, cloned to ~/.config/setthemacup. On a new Mac the Private settings step logs in with gh and clones it, so there's nothing to type. The very first time, it asks each value below once and creates that repo for you. The daily sync pushes any edits.

GIT_NAMEGitHub username required
GIT_EMAILPersonal git email required
WORK_GIT_NAMEWork git name (empty = no work identity)
WORK_GIT_EMAILWork git email
WORK_DIRFolder that holds work repos
WORK_SSH_HOSTWork GitHub SSH host alias
WORK_SSH_KEYWork SSH key file name in ~/.ssh
NOTES_JOURNAL_DIRQuick-notes folder
NOTES_PROJECT_DIRProject notes vault (optional)
SMB_SHARESSMB shares to auto-mount, "name=smb://host" space separated (optional)
FLOWD_JOURNAL_REMOTEflowd journal repo, e.g. git@github.com:you/journal.git (optional)
FLOWD_MACHINEflowd machine folder

Afterwards

Running it again

setup is on your PATH once the first run finishes. The end of every run shows a short list of things only a person can do (sign-ins, permissions, a restart), also saved to ~/.setup/logs/next-steps.md.

Usage: setup [options]

  -y, --yes          run everything, no checklist or prompts
  -n, --dry-run      show what would run; change nothing
  -l, --list         show each step and whether it's done
      --sync         update the package/skill lists from what you installed or
                     removed by hand (runs daily; -n to preview)
      --only a,b     run only these steps (Homebrew always runs)
      --skip a,b     run everything except these
  -h, --help         this help
